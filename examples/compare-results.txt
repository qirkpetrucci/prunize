📊 OVERALL SUMMARY
================================================================================

🔍 Key Findings:
✓ prunize automatically detects best format (TOON/compact) based on data structure
✓ @toon-format/toon uses consistent TOON format for all data
✓ For array of objects: Both produce identical TOON table format
✓ For simple objects: prunize uses compact format, toon uses TOON format
✓ Token efficiency is mostly tied, with trade-offs based on data type
✓ Both significantly reduce tokens vs JSON (40-60% reduction)

📈 Performance Characteristics:
prunize:
  - Auto-detection chooses optimal format per data structure
  - TOON format for arrays/tables (same as official)
  - Compact format for simple key-values (more efficient)
  - Best for: Mixed content, auto-optimization

@toon-format/toon:
  - Consistent TOON format across all data types
  - Better human readability and consistency
  - Bidirectional support (encode + decode)
  - Best for: Standard format, round-trip conversion

💡 Recommendation:
Use prunize for: Maximum token efficiency with auto-format detection
Use @toon-format/toon for: Standard TOON format with decode support
Combine both: prunize for optimization, toon for standardization
